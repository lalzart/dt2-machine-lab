# Capicola preparation on sample selection

2026-10-08 revision 1. The user authorized continued implementation. Source-reimplementation of the existing licensed twelve-second mono adapter; original core, oracle, old families and CPU image are preserved.

Primary claim: a selected eligible sample can reach READY through normal audio frames before any trigger or assignment of the selected sample to a voice. Read the track-one cached SAMP halfword at 0x2559bc (working command copy 0x2558dc + wire0xe0), then the OS1.16 slot table at 0x257810 + slot*20. EVIDENCE: the stock trigger path uses that slot and table, as recorded in DigiKit finding15. Validate this mapping through captured CPU commands and actual LP0 transfers. Accept only project slots0..1023, identical mono offsets, stereo byte0, 48000Hz, even byte lengths, 141..576000 frames and complete containment in the reduced sample pool. Invalid/unsupported sources remain silent and never begin analysis. Preview slot1024 is excluded.

Introduce optional family capicola-selection. Reuse the existing two-pass worker, automatic sample-event invalidation, publication epochs, panel controls and owned-state layout. Add narrowly scoped default-preserving source/validity hooks to the automatic adapter. Selection identity must match the bank when rendering; live voice pointers must also match before playback. Selection changes cancel incomplete work, leaving the old voice silent. Same-address reloads must clear readiness and rebuild. Stock and Plaits paths stay unchanged. Preparation budget remains32 input positions per32-sample block and maximum sample duration remains12 seconds. Do not change musical behavior or queue triggers.

Expose a versioned native preparation-status record in existing reserved working RAM (old logical0x200e4600, relocated with other state), containing sequence, magic/version, slot, state, rejection reason, completed/total preparation positions, epoch, source and frames. States: off, empty, unsupported, preparing, waiting for sample reload, ready, failed. Progress spans both passes including their four padding positions. A sequence guard permits a consistent snapshot; event invalidation is authoritative in HANDOFF and reflected in status on the next maintenance frame. This is emulator-readable feedback, not yet an on-device display. Do not repurpose an unverified CPU/DSP reply field.

Acceptance: exact repeated new builds; unchanged previous legacy and reserved-state image hashes; native LP0 loading followed by trigger-free SAMP frames reaches READY with previous voice pointers unchanged and different from the selected sample and exact host keys; first later trigger produces the expected complete stereo voice buffers at the stock one-block latency with max error1e-4 and RMS1e-5; reload and mid-prep slot change discard stale work; invalid slot, empty, stereo, unsupported rate, oversize, too short and out-of-pool metadata fail closed; current selection prevents stale playback; progress is bounded and monotonic within a generation. Parameter changes retain existing controls. Compare stock types0/6 and all six Plaits models to the preserved build. Preserve former-L2 poison and stack guards. Run source units and SINE replay. Fixed fixtures: capicola-panel-08 commands, capicola-panel-05 LP0 sample transfers; additional explicit synthetic metadata only for negative controls. Deterministic seed1;32-sample blocks at48000Hz. Keep binaries/captures/reports under unique ignored out/runs paths and record source/image hashes.

UNRESOLVED: actual screen feedback needs a separately evidenced DSP-to-CPU transport and UI integration; L2 code ownership, coupled cold startup/persistence and physical deadlines remain open. This stage does not create an installable release, increase allocation, flash, commit or publish. Existing frozen core equivalence, license/source locks and signal tolerances remain binding.
