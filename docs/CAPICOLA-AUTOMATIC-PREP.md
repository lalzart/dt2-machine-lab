# Capicola automatic preparation

2026-10-08 revision 1. The user requested continued implementation. This extends the reserved-memory prototype with automatic source detection and bounded native preparation. It deliberately changes the earlier harness-only scheduling design: a 32-input-frame preparation slice runs at the end of the stock audio block, before its elapsed-time capture. It is audio-task work, not a background RTOS task. Physical deadline safety is unproven; the emulator must report incremental instruction counts. At 32 output frames/block and 48 kHz, two complete passes over 12 seconds require approximately 24 seconds of uninterrupted preparation. Playback is silent until publication; a later trigger starts the prepared sample. No delayed trigger is synthesized.

OS1.16 only. The existing combined Plaits/Flex image and eight-MiB sample-pool reservation remain the baseline. A new optional DSP family leaves previous families byte-identical. Track1/type8 and one shared mono bank remain the scope. Use voice0 source and frame count, require voice1 source to match or be absent, reject pointers outside the reduced stock sample pool and lengths outside 1..576000. Source is contiguous signed int16, stride1; the stock slot getter divides byte length by two before assigning voice length at +0x188. Default controls remain pitch1, advance1, gain0.125, leash128 pending CPU control integration.

Hook normal block completion at SHARC 0x1c75a2, replay MODE1 clear before C and resume 0x1c75a5. Save and restore register context using a separate wrapper scratch/stack. Native sample page-copy entry0x1c403c and slot-header entry0x1c3fe5 notify a small interrupt-safe event handler before displaced instructions. These hooks use a separate scratch/stack from maintenance and voice rendering. An overlapping page clears ready and changes an epoch before stock copies PCM. It blocks preparation until a matching completed slot header arrives. The header must cover the tracked source and match its byte length; a mismatched replacement remains blocked until the voice acquires its new identity. Unrelated transfers must preserve a ready bank. Page/header handlers never modify analyzer or bank arrays. A step whose epoch changes is cancelled before publication; bank mutation and rendering serialize in the audio task.

Initialize once from zero boot state. Source/type/length changes cancel old readers and restart preparation. Repeated same identity retains a ready bank. Count, exact array binding inside the reserved span, write, and publication are automatic. Polling has a fixed 32-frame step limit; no whole-sample loop or allocation is introduced. Failure remains silent without retrying the same failed identity indefinitely. Slot reset/header invalidation must clear stale publication. Never restore these raw pointer states across a project or process restart.

Validate exact repeated builds, guarded hook bytes, original-family parity, compiled keys versus host oracle, actual stock frame-driven progress without service commands, ready-bank render parity, changed pointer/length/type, invalid range and stereo rejection, overlapping/nonoverlapping page transfer, reset and same-address replacement, cancellation between passes, unchanged stock/Plaits output, unit suite and SINE replay. Freeze existing signal tolerances max1e-4 RMS1e-5; exact int16-derived keys required. Record worst observed instruction counts separately for preparation and full blocks. CPU menu and control transport follow this integration; no installable or physical-device claim is made by these checks.

The loop-guard copy at0x1c400f also receives an overlap notification before the stock sample-end copy at source+length. The hook conservatively protects 16 bytes; the observed stock copy writes 10 bytes. Zero-length slot resets invalidate even when their offset is the stock0xfffffc00 sentinel. Reader validation checks current length and mono-lane identity as well as publication epoch, so changed metadata cannot play one block from the old bank.
