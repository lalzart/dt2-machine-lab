# Plaits virtual-analog experiment

Authorization: the user accepted the single-engine feasibility proposal with
“Let’s try” on 2026-10-05. This is a source port in the existing machine lab.
The scope is one original virtual-analog engine, one track, offline audio.
No hardware, publication, full Plaits voice, or multi-track capacity claim.

## Selected architecture and working definition

EVIDENCE: upstream `VirtualAnalogEngine` uses `VA_VARIANT 2`: three variable
shape oscillators and one variable saw, producing OUT and AUX. The upstream
C++ implementation is the reference; a C99 translation is the candidate for
the pinned Selache compiler. Dependencies remain unchanged. All copied code
retains Emilie Gillet's MIT notice. Exact upstream files and revisions are
recorded in `machines/plaits-va/source-lock.json` before translation.

INFERENCE: a C99 translation is the smallest locally available route to a
compiled SHARC engine. A small floating-point kernel must execute correctly
before trusting a larger build. Compiler/interpreter failures may limit this
iteration; retain the first failing fixture and report the actual layer.

Working artifact: `out/runs/<unique>/plaits-va.wav`, generated by executed
SHARC instructions and compared with a host render. Host-reference audio is
an earlier deliverable and must be explicitly identified. The firmware adapter
is a later check of the same core; standalone native SHARC execution alone
does not demonstrate machine integration.

## Frozen behavior and deliberate boundaries

- Preserve upstream VA variant 2 equations, update order, BLEP corrections,
  detuning table, pitch lookup bytes, oscillator initialization and float32
  interpolation, including interpolation's accumulated end state.
- Preserve both OUT and AUX in the reference/standalone comparison. Main OUT
  is the initial firmware source. No Plaits LPG/envelope, other models, panel,
  CV decoder, user-data storage or hardware driver is in this engine port.
- Initial comparison uses 12-sample blocks, the upstream pitch calibration
  (`47872.34 Hz`) and source sample order. A 48 kHz WAV has the upstream
  calibration offset; do not silently claim concert-pitch correction.
- Firmware adaptation may render these 12-sample blocks into a FIFO and
  duplicate 48 kHz samples into the existing 96 kHz work buffer. This is an
  explicitly experimental rate adapter; final stock decimation is unverified.
- Fixed, preallocated state and scratch; no heap allocation or random source
  in the core. C structs replace classes; explicit interpolation commit replaces
  destructors; lookup arrays replace external C++ namespace symbols.
- Init resets all state. Upstream engine Reset is a no-op. Any wrapper note
  envelope/reset is separate from engine equivalence. Panic/switch-away must
  silence the wrapper and clear its active flag. Freeze, recall, reconnection,
  model changes and external MIDI are excluded from this first engine test.
- Host/target state equivalence means matching output over the named input
  timeline within tolerance, not matching C++ object bytes to a C struct.

## Controls and literal experiment

Core inputs are note (MIDI semitones), harmonics/timbre/morph in [0,1]. Start
with note 60 and all macros 0.5. Trigger/accent do not affect this engine's
continuous oscillator directly. The host experiment supplies semantic values;
these are not claimed to be real panel input or stored locks.

Render a 4-second deterministic sequence, 16000 blocks of 12 samples at
48 kHz. At block 0 use (60, .5, .5, .5); at 4000 use (48, .2, .15, .8);
at 8000 use (67, .8, .9, .2); at 12000 use (60, .5, .5, .5).
Order is (note, harmonics, timbre, morph). Additional independent fresh-state
short comparisons cover note 0/127 and macro corners 0/1. No stochastic seed
is required. A disabled-output comparator must fail the nonzero reference
comparison. Reinitializing and replaying must reproduce candidate PCM exactly.

Freeze tolerances before translation: host C versus original C++ maximum
absolute error <= 1e-5; SHARC versus host C <= 2e-3 over a short 120-block
vector, reporting RMS and first mismatch as well. No automatic tolerance
relaxation; a failure remains a failure until explained. All samples finite;
raw engine peak < 4. Output WAV preview gain 0.2, separate from raw comparison.
For a full long target render, report measured divergence separately rather
than assuming oscillator phase remains bit-exact across floating-point targets.

### Integration and controls

`P-VA` is an alternative custom machine in type-7's experimental slot; it
does not coexist with SINE as another allocated type. Its named CPU image is
built with 51 guarded writes, SHA-256
`937cdc9cc1467e39157cdce959c6cc46d139a93b04acede99c5bdb4363d241f3`.
That label has not been boot/UI-tested. The proven control capture is still
the earlier SINE type-7 CPU image. Its type and control format are reused.

TUNE, LEN and LEV use the existing SINE control conventions. The new wrapper
also reads harmonics, timbre and morph from borrowed wire slots `0xdc`, `0xe0`
and `0xe2`, each divided by 32768 and clamped to [0,1]. They latch at trigger.
The observed inherited macro values were approximately `.0234375`, `.0002136`,
and `0`; this experiment did not drive those knobs or store macro p-locks.
Proper descriptors/labels and real macro p-lock capture are the next control
task. The three captured pitch values were 42.40625, 65.9921875, 42.40625 MIDI
semitones; wrapper length and gain also followed the stored CPU values.

Per-lane state is 384 bytes: the 252-byte engine, controls, a 12-sample OUT/AUX
FIFO, cursor, envelope timing, active flag and gain. Each trigger initializes
the engine and resets the FIFO/envelope. The wrapper's 5 ms attack/release
and 10–500 ms length are explicit lab behavior, not the Plaits LPG.

The wrapper saves the stock register context, uses a separate C stack, calls
the compiled source, restores the context and rejoins the stock source path.
Other tracks' event bits are masked in replay because the prepared factory
pattern reaches an unsupported native instruction when those tracks trigger.
Track-1 control words and the retained raw CPU capture are unchanged.

### Resources and toolchain findings

The standalone linked code is 10,368 bytes; integrated code is 13,928 bytes.
Initialized data is 2,076 bytes. The experiment deliberately reserves a large
466,944-byte address span with holes, a private stack, context and state;
this is not a minimum memory requirement or a verified free-memory allocation.
Only stock-loader disjointness was checked. Runtime memory ownership on the
device remains unresolved.

The standalone core retired 21,130–23,545 emulator instructions per 12-sample
block in the four-second run (mean 21,886.34). These include the diagnostic
entry wrapper and are not hardware cycles or DSP utilization. Physical clocks,
memory stalls, other voices and the full firmware workload are unmeasured.

A small compiled C kernel passed before the engine port. Initial full-width
assembly failed: applying `.NOCOMPRESS` globally caused this assembler to emit
NOPs at RFRAME sites. Selectively expanding standalone integer additions
preserves compressed RFRAME and avoids the already-known ADD disagreement.
All linked instruction extents agree with the pinned DigiKit decoder. The
failed diagnostic is retained in `out/runs/plaits-target-first/`; the successful
isolated diagnosis is in `out/runs/plaits-target-selective/`. Neither dependency
was modified.

Final verification: eight existing harness tests and the full SINE replay
suite pass; the latter is recorded in
`out/runs/20261005T054119Z-test-3922e65a/manifest.json`. Lint/format checks pass
for the new Python files. Regenerating the C/header/tables into a separate
temporary directory reproduces the checked-in source bytes exactly. No new
general test framework, dependency changes, commits or device writes were made.

### Repeat commands

The local source checkouts are ignored. To provision them on another checkout,
clone the upstream eurorack repository into `.local/sources/eurorack`, check out
the exact revision above, and initialize only its pinned `stmlib` submodule.
The existing lab private fixture and configured Python are also required.

```sh
./labctl doctor
python3 machines/plaits-va/translate.py .local/sources/eurorack
python3 scripts/try-plaits-va.py out/runs/my-plaits-host --mode host
python3 scripts/try-plaits-va.py out/runs/my-plaits-target --mode target
python3 scripts/try-plaits-va.py out/runs/my-plaits-firmware --mode firmware
```

Each output directory must be new. `--blocks 120` provides a short standalone
run; the default is 16,000 blocks/four seconds. Builds use the pinned Selache
C99 compiler, built into ignored `out/cache/selache-c99`, and the existing
assembler/linker. Reports retain source/tool/image/PCM hashes, observations,
comparators and failures. The firmware mode also builds the named CPU candidate
but does not boot that image, package a firmware container or flash hardware.
